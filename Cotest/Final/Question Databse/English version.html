In algorithm competitions and interviews, it's often said that "designing the state is half the battle won; deriving the transition equation is the whole solution." If you've recently mastered 1D frequency DP (Boredom), interval DP (Clear the String), and the hellish contour DP (Pebbles), you've subconsciously grasped the essence of state design.

The core of abstracting a universal "mindset" for DP state design boils down to four words: information compression.

You need to condense the long and complex history of past choices into a few extremely concise dimensions, just enough to make the perfect decision for the next step.

When faced with a brand new DP problem, you can derive the state using this four-step framework:

Step 1: Find the "Stage" (Define the Main Dimension)

Any DP is a continuously advancing process. You need to find that "irreversible unidirectional timeline."

• Ask yourself: In what order does the problem grow in scale? • Common Main Dimensions:

• Prefix/Suffix: Processing the $i$-th number (e.g., the number $i$ in Boredom).

• Interval Length: The size of the subproblem expands from a short interval to a long interval (e.g., $len$ in Clear the String).

• Tree Level: Summarizing from leaf nodes to the root node.

• Starting Strategy: First, boldly assume the state is dp[i] (representing the optimal solution for the first $i$ elements), or dp[i][j] (representing the optimal solution for the interval $[i, j]$).

Second Step: Finding "Binding" (Adding Additional Dimensions)

This is the most challenging step. If you try to write the state transition equation using the dp[i] from the first step, you'll usually find yourself unable to continue because you lack information.

• Ask yourself: When I made the decision at the $i$-th step, what past factors limited me? • Targeted Dimensional Upgrading:

• Capacity Constraints: If the selected item is subject to weight constraints, add a one-dimensional weight $\to$ dp[i][w] (Knapsack problem).

• Adjacent Exclusion: If the current cell is constrained by the color of the previous cell, add a one-dimensional color $\to$ dp[i][color].

• Two-Dimensional Spatial Constraints: If the current cell is constrained by the shape of the previous $N$ cells, add a one-dimensional binary outline $\to$ dp[i][mask] (this is what you learned in Pebbles).

• Core Rule: Add the dimension corresponding to the missing constraints. But keep the number of dimensions as small as possible, otherwise you will face state explosion.

Step 3: Soul-Searching Question (No Aftereffect Test)
After designing the state, a stress test with "no aftereffect" must be performed.

• Thought Experiment: Suppose there are two completely different paths that eventually reach the same state (e.g., both reach dp[5][10]). Continuing from this state, the future options and the highest possible score for both approaches must be exactly the same.

• **Risk Prevention:** If both approach A and approach B have reached step 5, but approach A cannot proceed further due to a previous action, while approach B can, then your state does not fully encompass all the "bonds." (Recall: If you use dp[i][j] to perform Pebbles, and when you reach dp[2][3], you don't know if the top right corner was previously occupied; this is a typical failure to pass the no-aftereffect test and must be upgraded to a mask).

**Fourth Step: Clarify the Physical Meaning of the "Value"** Now that the state coordinates [] are clearly defined, the next step is to clarify what the value stored in this array actually is.

• Usually, the value is what the question asks (e.g., maximum integral, minimum cost, total number of solutions). • Be sure to clearly write it in natural language in the comments, for example: "dp[i][mask] represents the maximum score that can be obtained when considering the first $i$ cells and the state of the last $n+1$ cells is mask." As long as this sentence is written perfectly, the recurrence relation is just a translation of this sentence into code.

💡 Common Problem Types and State Design "Formulas" (Cheat Sheet) Based on the problems you've recently worked on, here's a set of intuitive mappings for you:

1. "Choose or not choose, no cross-boundary" $\to$ One-dimensional linear DP

• Characteristics: Only affected by the previous one or two states.

• State: dp[i]

• Example: Boredom (a variant of the robbery problem).

2. "Eliminate, merge, and both ends can be pieced together" $\to$ Interval DP

• Characteristics: Operations can hollow out the middle, making elements that were not originally adjacent together.

• State: dp[i][j] (always from a shorter interval to a longer interval). • Example: Clear the String.

3. “Grid graph, constrained by non-aligned boundaries such as diagonals or horse-and-sun patterns” $\to$ State Compression / Contour DP

• Features: The mutual influence between rows is interwoven like jagged teeth, and the width $N$ is extremely small (usually $\le 20$).

• State: dp[i][mask] ($i$ is a row or cell, $mask$ is the contour of the cross section).

• Example: Pebbles.

I. 0-1 Knapsack

Core Philosophy: Take it or leave it. Each item is unique and there is only one of each.

• State Definition: dp[j] represents the maximum value obtainable with a capacity of $j$.

• State Transition: dp[j] = max(dp[j], dp[j - weight[i]] + value[i])

• Golden Rule: The inner capacity loop must be in reverse order (from largest to smallest).

• Why reverse order? To physically cut off "spacetime pollution". When calculating the large capacity, the referenced small capacity state must be a historical record from the previous round, ensuring that the current item is never repeatedly accumulated.
36
II. Complete Knapsack
Core Philosophy: As long as the capacity is sufficient, you can take as many of the same item as you want.

• State Definition: dp[j] represents the maximum value (or number of solutions) obtainable with a capacity of $j$.

• State Transition: dp[j] = max(dp[j], dp[j - weight[i]] + value[i]) (find the maximum value) or dp[j] += dp[j - weight[i]] (find the number of solutions).

• Golden Rule: The inner capacity loop must be in ascending order (from smallest to largest).

• Why ascending order? Because we need "spacetime pollution"! When calculating a capacity of 4, if we use the result of a capacity of 2, and a capacity of 2 just contains one item A, then a capacity of 4 actually contains two items A. Ascending order perfectly matches the physical meaning of "infinitely taking". ⚠️ The Pitfalls of Complete Knapsack Problems: Permutations vs. Combinations

Just like what you might encounter when working on the Coin Combinations series:

1. Calculating the number of combinations (unordered, 2+3 and 3+2 count as the same):

• Iterate through the items in the outer layer, and iterate through the capacity in the inner layer in ascending order.

• Logic: Coins are taken out in order. First, fill the ledger with 2, then fill it with 3. This forcibly defines the order of taking coins, completely eliminating duplicates.

2. Calculating the number of permutations (ordered, 2+3 and 3+2 count as two):

• Iterate through the capacity in the outer layer, and iterate through the items in the inner layer.

• Logic: Under each given capacity, all coins compete fairly. Taking 2 first and then 3, and taking 3 first and then 2, will be counted repeatedly in different capacity stages.

III. Multiple Knapsack

Core Philosophy: The number of items is not unlimited, but it's not limited to just one; there are specific inventory constraints (e.g., you can take a maximum of $k$ items of A).

• Simplest Solution: Treat it as a 0-1 knapsack problem. If there are 5 items of A, we treat them as 5 completely independent items, A1, A2, A3, A4, and A5, each taken only once.

• Fatal Flaw: If $k$ is very large, the time complexity will explode.

• Advanced Optimization (Binary Splitting): Instead of actually splitting it into $k$ items, we use the principle of binary concatenation to pack them.

For example, if there are 13 items of A, we don't need 13 independent A's. We pack them into 4 packages with capacities of 1, 2, 4, and 6 (the remaining items).

If you want to take any quantity between 1 and 13, you can use these four packages to precisely construct the result using a 0-1 knapsack problem (for example, to take 7 items, you would use 1+2+4). In this way, the original $O(N \times K)$ decomposition is instantly reduced to $O(N \log K)$.

IV. Group Knapsack

Core Philosophy: Items are divided into several mutually exclusive "schools." Each school has many disciples, but you can only take one disciple from each school at a time.

• State Transition: dp[j] = max(dp[j], dp[j - weight[k]] + value[k]) (where $k$ is an item in the current group).

• Nested Golden Rules:

1. Outer Loop: Iterate through all groups.

2. Middle Loop: Iterate through the capacity (**must be in reverse order!** Because different groups have a 0-1 knapsack relationship, they cannot be mixed up).

3. Inner Loop: Enumerate all items in the current group.

• Why put the capacity in the middle? This ensures that, within the same capacity $j$, all items in the current group are competing with each other (because the middle loop locks $j$, and the inner loop takes turns using different $k$ to try updating dp[j]). The item that remains at the end is definitely the most powerful disciple in the group, perfectly guaranteeing that each group selects at most one.
